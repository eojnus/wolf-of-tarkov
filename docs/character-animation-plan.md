## 3. 动作交付

语义动作映射集中在 `src/content/config.ts#PLAYER.model.clips`；当前配置：

| 语义 | 来源 | 说明 |
| --- | --- | --- |
| `idle` | **原动画裁剪** | 取源片段 0–1.5 s，循环；移除骨骼根的平移/旋转/缩放轨道，避免与物理位移重复 |
| `walk` | **程序化** | 无源片段；按实际水平速度推进步频，髋/膝/踝/肩/肘姿态 |
| `run` | **程序化** | 无源片段；独立振幅、屈膝和手臂摆动，不是把行走动画简单加速 |
| `jumpStart` | **程序化** | 由物理 `leftGround` 且竖直速度为正触发；起跳伸展→空中姿态 |
| `airborne` | **程序化** | 由实际离地状态进入；接近顶点收腿，起跳/下落阶段伸展 |
| `land` | **程序化** | 由物理 `touchedGround` 触发；屈膝缓冲并临时下沉 `inner` 组，使脚底保持贴地 |

没有使用骨骼重定向、没有引入 Mixamo、没有新增独立派生动画资产。程序化姿态的生成方式、角度与速度参数都在 `config.ts` 与 `character.ts` 中可审查。

## 4. 跳跃状态传递

数据流：

```
physics.advance(...)
  → PhysicsStepResult {
      grounded, verticalVelocity,
      leftGround, touchedGround, steps, ...
    }
  → World.update
  → Player.updateFromPhysics
  → CharacterRig.update
```

- `verticalVelocity`、`leftGround`、`touchedGround` 是**只读表现信息**，不改变物理求解、跳跃高度、重力、移动速度或碰撞尺寸。
- `leftGround` / `touchedGround` 在每个固定物理步比较前后 `grounded` 后累计；同一渲染帧多个物理步的起跳/落地不会被帧末状态覆盖。`steps = 0` 的帧不会重复触发事件。
- 动画不使用 `jumpHandled` 判断起跳成功：该字段可能表示请求被处理或丢弃；实际离地/接地只认物理步变化。
- 暂停/冻结时 `World` 给 `Player` 的动画 dt 为 0，`CharacterRig.update` 直接返回，姿态停在最后一帧；业务面板打开时水平输入被锁，但竖直物理继续，动画仍消费接地变化。
- 读档、场景切换、位置恢复调用 `CharacterRig.reset()`，清除起跳/空中/落地阶段与程序化权重；不新增存档字段。

## 5. 混合、根运动与资源

- 地面：idle 作为底层姿态；走/跑片段缺失时用程序化姿态按权重覆盖受控骨骼，权重以约 0.16 s 时间常数淡入/淡出。走与跑之间用 `sprinting` 平滑过渡，步频由实际水平速度与步幅换算，并限制在配置的上下限。
- 空中：跳跃阶段权重优先，地面走/跑不会与空中动作同时争夺骨骼；落地后先维持 0.22 s 缓冲，再回到 idle/走/跑。
- 源片段中骨骼根的平移、旋转、缩放轨道被移除；程序化姿态也不写根位移。人物位置、朝向、碰撞、重力和跳跃仍只由 `world/physics` 与 `Player` 决定。
- 资产由 `loadCharacterRig` 统一加载：`.usdz` 走 `USDLoader`，其他扩展名走 `GLTFLoader`；两者都整理为 `{ root, clips, dispose }`。
- 释放：`dispose()` 停止 mixer、清理 mixer 缓存、释放网格几何、材质与贴图，并撤销 USDZ 纹理的 blob URL；只释放该角色子树拥有的资源，不触碰城市场景共享资源。`Player.dispose()` 先从玩家组移除根节点再释放。
- 桌面协议：`desktop/main.cjs` 的 MIME 表新增 `.usdz → model/vnd.usdz+zip`；CSP、沙箱、`webSecurity`、路径限制和固定来源未改动。

### 转向修复确认（2026-10-31 追加，本次未启动游戏）

**本轮启动/截图：0 次。** 未结束任何游戏进程，未读取或写入玩家生产存档；仅执行代码审查、Node 局部检查、类型检查/构建和 Electron 打包。

**根因**：程序化姿态原先绕固定世界 X/Z 轴旋转。人物朝向改变后，骨骼仍按世界轴摆动，因此只在某个朝向下看似正常；这不是某个角度的相位问题，不能用反向角度补丁解决。`Player` 本身在 `CharacterRig.update` 之前写入 `group.rotation.y`，转向同步顺序是正确的；问题在动画侧的轴选择。

**修改**：

- `CharacterRig` 每帧从角色 `inner` 的世界四元数取本地 X/Y/Z 轴（`updateCharacterAxes`），走、跑、跳、脚掌回正和跳跃手臂外展全部使用这些轴；不再使用常量世界轴。
- `Player.updateFromPhysics` 保留“先 `applyTransform()` 写入朝向，再 `character.update()`”的顺序，并加注释说明该不变量。
- 走、跑、跳跃共用同一套坐标；没有为单个角度增加反向补丁。

**非渲染局部检查**（Node + 真实 USDZ 骨骼 + 真实 `character.ts`/`player.ts`，无 renderer、无游戏启动）：

- walk / run / jump 在角色朝向 0° / 90° / 180° / 270° 时，足部与手部相对角色根的最大位置差：walk ≤ 1.3e-9 m，run ≤ 6.1e-9 m，jump ≤ 1.7e-8 m。
- 连续 0°→90° 转身（24 帧）与固定 90° 控制序列逐帧比较，最大差 3.1e-9 m。
- 经真实 `Player.group` 朝向同步的四方向 walk 检查，最大差 2.3e-9 m；`Player.group.rotation.y` 对
  `(0,+5.4)`、`(+5.4,0)`、`(0,-5.4)`、`(-5.4,0)` 分别收敛到 0、π/2、π、-π/2，最大误差 1.1e-8 rad。
- 结论：**当前源码的骨骼空间姿态在四个方向一致，转身无翻转，Player 朝向同步正确**。这是数学/骨骼空间检查，不是四方向游戏视觉验收。

## 10. 验收

严格遵守非必要不测试原则：整个实施与验收期间启动游戏最多三次，用于观察人物和动作；计划合并观察场景，不为每个检查项重复启动。其余内容优先通过代码与资源静态审查，未实际运行的项目如实标记未验证；不要为性能、存档、安装或完整回归额外启动游戏。按项目交付要求执行一次类型检查与生产构建，构建不计作启动游戏。记录每次启动的目的和结果、动作来源、授权、尺寸、面数与不足；不得把未经观察的视觉质量或性能写成通过。
