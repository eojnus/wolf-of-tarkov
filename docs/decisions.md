## D97 · Rapier 运动学角色控制器替代二维人物移动（2026-10-30）

**决策**：引入 `@dimforge/rapier3d-compat`（0.21.0，Apache-2.0，WASM 内嵌 base64），
在 `src/world/physics/` 建立唯一物理运行时。人物使用胶囊 + 运动学角色控制器，胶囊总高
1.78m、脚底为刚体原点；室外半径 0.42、室内 0.30。重力、竖直速度与跳跃由项目代码维护，
固定步长 1/60s，真帧最多采信 0.1s、最多 6 子步。物理保留相邻两个已完成步的权威位置，
表现位置按剩余累计时间插值，只供人物显示与镜头使用；动画消费物理步实际水平速度。

**理由**：现有二维 AABB 无法表达跳跃、头顶和可站立面；角色控制器可直接消费现有
`Collider` 的规划包络/装饰/家具数据，避免从可见模型反推。旧二维列表仍可服务家具编辑的
连通域与安全落点，但不再写人物位置。

**代价**：WASM 使主包增至约 5.8MB（gzip 约 2.1MB）；Rapier 初始化失败时人物必须保持锁定，
不能回退到旧移动。家具/布局提交需要整体重建静态体；室内门头/天花板需要与相机遮挡分开的
物理专用盒。跳跃手感、可站立家具范围和镜头跟随仍由用户运行验收。

**边界**：高度、竖直速度、接地状态与物理句柄不进存档；空中保存仍按地面恢复，读档用静态盒
支撑查询派生落点，`WorldSaveData` 与 `SAVE.formatVersion = 20` 不变；不实现车辆或动态物品。

**集成修正**：物理步速度样本与显示插值分离，无物理步时保留有效速度；接地、传送和编辑恢复
均用胶囊向下扫掠检查真实支撑，并检查身体/头顶空间。保存只读派生安全 x/z，无法验证时拒绝
写档；静态抑制同步移除 Rapier 碰撞。读档等待最终碰撞就绪期间冻结人物物理，经济照常推进。

**有限验证**：真实 WASM/物理运行时下短时检查 60/120/144/240Hz 与变化帧时间，直跑动画速度
稳定约 10.8m/s、无错误待机；检查撞墙停止、暂停冻结、跳跃落地和碰头。以 World 方法局部调用
检查延迟初始化、高处编辑保位、收纳支撑、安全快照恢复、街区抑制与退出室内回归。类型检查和
生产构建通过；未启动浏览器，画面残影、镜头及实际模型体验仍由用户运行验收。

## D98 · Windows 桌面化使用 Electron 外壳与稳定的 app://game 来源（2026-10-31）

**决策**：保留 Three.js + Vite 渲染层，新增 `desktop/main.cjs`、沙箱 `desktop/preload.cjs` 与
`src/platform/desktop.ts`。生产页面来源固定为 `app://game`（standard + secure），由
`protocol.handle` 只服务 `dist/` 内的 GET/HEAD 文件；开发只连接固定的
`http://127.0.0.1:5173/`，并以单独的用户数据目录隔离。存档继续使用现有 IndexedDB 与
`SAVE.formatVersion = 20`，不建立第二套存档，不自动读取浏览器数据。

**理由**：Electron 自带的 Chromium 与现有 WebGL/Three.js 兼容；固定标准协议使 IndexedDB
有可持久化的来源，避免 `file://` 的不透明来源与相对资源问题。只增加关闭前等待这一项
preload 能力，可以避免关闭窗口时截断正在进行的自动保存，同时不把通用 IPC 或 Node.js
暴露给游戏代码。

**安全边界**：`contextIsolation`、`sandbox`、`webSecurity` 全开，`nodeIntegration` 关闭；
禁止任意导航、新窗口、webview 与非必要权限请求；唯一权限例外是主窗口固定来源的
`pointerLock`（游戏视角必需），其余一律拒绝。IPC 只有 `desktop:before-close` /
`desktop:close-ready` 两条固定消息，并校验发送者。CSP 只放开现有 UI 必需的内联样式、
Rapier WASM 编译与 GLTF 的 Blob 读取，没有关闭安全机制。

**关闭与存档并发（2026-10-31 修复）**：渲染进程用 `pendingSaves` 跟踪手动与自动存档的
完整操作，关闭回调循环等待集合清空；手动保存从调用时刻（包括等待已有自动保存的阶段）
就纳入等待，避免只等待 `autosaveChain` 而漏掉独立的手动写入。主进程仍以 4 秒为上限，
超时记录日志并退出；失败由现有 `performSave` 提示，不报告保存成功。

**代价**：桌面版与浏览器版存档不互通，迁移必须走游戏内 JSON 导入导出；安装包未签名；
只发布 Windows x64；关闭等待最长 4 秒，超时仍会退出，超过该时间的写入不保证完成。
自动更新暂不接入，未来更新必须保持 appId、用户数据目录与页面来源不变。

## D99 · 用原始 USDZ + 程序化基础动作接入 Alina（2026-10-31）

**决策**：玩家视觉模型改为 Sketchfab/Jungle Jim 的 Alina USDZ（CC BY 4.0），由
`USDLoader` 直接加载，保留 `GLTFLoader` 作为按扩展名选择的回退路线。源模型只有一段
22.63 s 的原地待机展示动作，因此 idle 取 0–1.5 s 循环；walk/run/jumpStart/airborne/land
用配置驱动的程序化骨骼姿态，不引入 Mixamo、不新建独立动作资产管线、不预建战斗系统。
`PhysicsStepResult` 只增加 `verticalVelocity` / `leftGround` / `touchedGround` 三个只读
表现字段，逐物理步累计接地变化；跳跃/落地表现依据物理实际事件，不使用 `jumpHandled`。
程序化姿态的旋转轴取**角色本地轴**（每帧随 `Player` 写入的朝向更新），不得使用固定世界轴；
否则人物转身后四肢仍会按世界方向摆动。

**理由**：直接加载 USDZ 避免在需求未确认时转换整条资产管线；原动作确实没有走/跑/跳，
复用、裁剪都无法得到可接受的前进动作，程序化姿态是当前最小且许可清晰的交付方式。
把语义动作映射集中在 `PLAYER.model.clips`，以后增加挥拳/持枪只需补片段或表现逻辑。

**代价**：程序化步态在 5.4/10.8 m/s 的游戏速度下存在脚底滑动风险；跳跃姿态幅度需要在
正式运行中验收；没有根运动与脚部 IK，不能宣称达到动作捕捉质量。USDZ 首次加载约 16 MB，
桌面协议必须提供 `.usdz` MIME；角色释放需自行处理材质/贴图与 blob URL。
