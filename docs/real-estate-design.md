# 房地产首版 · 实施设计

本文是 `docs/real-estate-task.md` 的实现设计（开发分支 `feature/real-estate`，起点 `0895cca`）。
只描述**本首版**如何落地；规则正文在 `docs/architecture.md`、`docs/contracts.md`，
决策理由在 `docs/decisions.md`。

## 1. 模块与状态权威

| 切片 | 位置 | 权威内容 | 不负责 |
| --- | --- | --- | --- |
| `realEstate` | `features/real-estate` | 房产与土地记录、产权主体、入住状态、挂牌、AI 土地报价、成交记录、玩家已实现价差 | 不保存余额、不算月度需求、不写满意度 |
| `housing` | `features/housing` | 3 个收入群组的家庭数、拥有/租住分配、购房意愿、月度住房指标 | 不保存群组余额（余额在 `finance`）、不保存第二份总人口 |

- 人口唯一权威仍是 `population.classes`；住房群组家庭数由阶层人数 ÷ 家庭规模**确定性派生**，每月同步。
- 空间唯一权威仍是 `cityLayout`：房产记录通过稳定 `buildingId` / `plotId` 关联布局，不复制几何。
- 资金唯一权威仍是 `finance`：群组以 `household:<groupId>` 主体账户记账（新增账户归属 `household`），
  卖方为 `investor:<id>`（晴川置业、城市土地储备中心、两家地产 AI）。
- `external` 仅用于宏观收入来源与居民消费去向，不冒充有资金约束的购房者。

## 2. 资金核算

| 流向 | 记账 | 个人月报 |
| --- | --- | --- |
| 玩家买住宅/土地 | 个人存款 → 卖方主体，`home-purchase` / `land-purchase` | 不计收支（资产形态转换） |
| 玩家卖住宅/土地 | 买方主体 → 个人存款，`home-sale` / `land-sale` | 不计收支；差额记 `realEstate.realizedCents` |
| 居民购房 | 群组账户 → 卖方主体 | 与个人无关 |
| 居民收入/消费 | `external:household-income` → 群组账户；群组账户 → `external:household-consumption` | 与个人无关 |
| AI 购地/购房 | AI 投资主体 → 卖方主体 | 与个人无关 |

- 每笔成交一次 `GameStore` 提交：付款、产权、入住、挂牌关闭、报价失效、流水、成交记录同时写入。
- 报价承诺用 `reserveFunds(..., ref = offerId)`，接受时 `transferReservedFunds` 只消费该单据。
- 宏观收入按稳定月度单据 `housing:income:<monthKey>` 入账一次；`housing.lastSettledMonthKey` 先判重，
  单据 id 作为第二道保险。工资口径只算一次：宏观收入是配置估计，**不**从企业工资额重复注入。
- 成本基础与已实现价差：`PropertyRecord.costBasisCents` + `PropertyTrade.realizedCents`；
  未实现估值另由 `valuationCents` 表示。净资产只计玩家持有物业估值一次。

## 3. 首版参数（`content/real-estate.ts`，均未做经济平衡）

- 家庭规模：低 3.4 / 中 3.0 / 高 2.6 人；月收入 5,000 / 11,000 / 26,000 元；
  月消费 3,800 / 7,200 / 16,000 元；初始人均家庭储蓄 12 万 / 42 万 / 120 万元。
- 储蓄档位：群组内按平均储蓄的 0.4 / 0.8 / 1.5 / 2.5 倍分布（权重 45/30/17/8%），
  用来限制"平均储蓄让所有家庭同时有购买力"。
- 户型：单间 30㎡ × 8,000 元/㎡、紧凑 62㎡ × 8,600、家庭 95㎡ × 9,200。
- 负担上限：价格 ≤ 年收入 × 6 / 5 / 4（低/中/高）。
- 晴川公寓 100 套 = 1 套永久居住权 + 99 套可售（单间 36 / 紧凑 44 / 家庭 20）。
- 住房新区每阶段交付 66 套（A 座 24、B 座 24、C 座 18）。
- 保护期：开局 99 套到第 7 个月月初；新区住宅自交付起 180 游戏日。
- 储备土地：4 块城市边缘地块（80㎡），基准 4,500 元/㎡；AI 报价有效期 30 日，溢价 2%～18%。
- 月度成交上限：每群组 6 套、全市场 12 套（需求/资金/供给限制之外的第二道闸）。
- 交易税费、持有税、租赁、抵押、私人开发：本首版不实现，也不预留空壳。

## 4. 月份执行顺序（`advanceGameTime` → `onMonthEnd`）

```
1 个人月结（房租已按永久居住权置 0）→ 企业月结
2 到期旧建设项目完成（housing 新区在此交付住宅单元）
3 城市统计与指数固化
4 人口月结（阶层人数）
4.5 住房月结（新增）：同步家庭数 → 收入/消费入账 → 估值更新 → 需求累积
    → 居民/玩家挂牌匹配成交 → AI 购房与土地报价 → 月度指标固化
5 政治满意度（新增 housing 输入：按收入阶层映射的住房压力）
6 提前选举检查 → 7 选举 → 8 建设判断 → 9 新窗口
```

- 逐月处理：跨多个月界时上述顺序按月重复，不会只按终点月份跑一次。
- 日界只做土地报价到期释放（`processHousingDay`），不重复累计需求。
- 不用 `setInterval` / `setTimeout`；不建第二套时间循环。

## 5. 迁移策略（存档 v16 → v17）

新增 `realEstate` / `housing` 两个切片与 `finance` 的 `household` 账户、6 个新流水类别。

- 群组由**迁移时刻**的阶层人数派生；群组账户按配置初始储蓄一次性注资；
- 晴川公寓 100 套、4 块储备土地、晴川置业/土地储备中心/两家地产 AI 账户一次性建立；
- 初始 99 套的保护期用「开局第 7 个月月初」的绝对时刻：已过该时刻的旧档自然不再受保护，
  不会重新获得整段保护期；
- 已完成住房新区的旧档按 `cityLayout` 补齐住宅单元（`deliveredAtMinute = 城区完成时刻`），
  幂等，读档不重复交房；
- 不重写历史月报、不追溯退款、不追溯减免旧房租；旧欠款保留；
- 迁移用深克隆，重复解析同一份旧档不会重复注资或重复发房。
