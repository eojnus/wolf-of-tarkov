## 最小实施方案

1. 在现有 CSS 令牌和组件选择器上建立石墨灰、克制透明度的视觉体系；复用 `icons.ts`，不加 UI 框架、字体网络依赖或视觉库。
2. HUD 保留实际已有信息和保存入口，仅移除右下角“个人”“菜单”。把整个时间操作组（暂停/继续、1/2/4 倍、休息 1 小时、睡到早上）移至 TAB 已有窗口标题附近的紧凑工具区，跨现有 TAB 栏目可达；不新增分类。沿用原命令与动作语义，休息/睡觉不擅自新增现场限制。HUD 时间继续显示。
3. ESC 沿用 PanelManager 路由与原有两项栏目，给 GameWindow 一个仅用于 `pause` 的表现模式。遮罩覆盖全屏，左侧约 340–440px 排列原导航、操作和必要进度，右侧留给城市背景；低高度屏幕允许左区滚动。暂停模式不拖动/放大，不影响 TAB 和业务窗口的拖动/放大状态。现有导航与分组层级原样保留，避免把两栏目拍平为新菜单。
4. 优先用已有 `isPaused()` 的菜单门控隔离临时暂停：`clock.paused` 继续表示玩家手动暂停，去掉菜单开关对它的覆盖；`clock.speed` 不因开关 ESC 改动。ESC 内 Space/时间命令不得改变手动暂停或速度；游戏信息仍属 `pause` 入口，持续暂停。从 ESC 切至 TAB 是离开暂停菜单，应恢复原手动暂停状态；普通 TAB/业务窗口不额外暂停。无需“保存后再恢复”第二份速度状态，也无需改时钟核心。
5. 审查每个真正退出点：继续、关闭、Esc、F、Tab、scrim、读取/导入成功、新游戏、鼠标解锁回调。保持重复打开幂等；异步读取/导入失败或取消留在菜单时持续暂停。场景/存档替换应采用新状态，不把旧菜单会话的暂停或速度回写新游戏。保留既有存档不持久化暂停的策略，本轮不修改存档格式。
6. 暂停时间不进入 `simAccumulator`，进出菜单重置 `lastFrameMs` 以避免边界帧带入等待时长；开菜单前的小数分钟可保留，但不得累积菜单期间 dt。后台继续沿用既有清零策略。禁止将 `advanceGameTime` 全局变为 `clock.paused` 时拒绝，因为休息等显式跳时有既有语义。
7. 移动端最小兼容提案：仅在触屏/粗指针设备上，于顶部安全区显示一个约 44px“界面”图标入口，展开两项“个人界面（TAB）”“暂停菜单（ESC）”，共用现有回调；开主窗口后收起。它只是替代入口，不是新的业务分类，桌面不常驻。关闭暂停后不让鼠标锁定遮罩挡住触屏入口。该提案随阶段 A 一并呈给用户，阶段 C 授权后实施；如用户调整方案，先按其选择修订。

## 设计约束

- 石墨面板建议 `#202629`，底板 `#161B1E`，主文字 `#F0F2F1`，次文字 `#B4BFBE`，强调色低饱和蓝绿 `#79ABA2`。这是起始规格，可按实际背景微调对比度。
- 正文约 14px、次级说明 12–13px、标题 20–28px，数字清晰且保留全部精度；不要用缩到难读的文字来弱化统计。
- 间距以 4/8px 节奏，圆角约 10–16px；主操作至少 44px 高，ESC 主按钮约 48–52px；统计背景、字号和字重低于可执行操作。
- 危险/涨跌等语义色保留原意义和文本辅助，不把“一种强调色”误解为移除语义区分。
- 背景轻透、细边框、少量阴影；默认不用全屏模糊，多层面板不叠加昂贵滤镜。右侧无装饰统计板、无无关内容、无霓虹科幻效果。
- 不改业务文案/类别/字段/统计口径/精度/排序；不能把买卖、现场办理和远程查看入口互换。
