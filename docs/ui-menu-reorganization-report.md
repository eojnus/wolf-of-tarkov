## 4. 迁移功能的新入口

| 功能 | 原入口 | 新入口 |
| --- | --- | --- |
| 行情（选股、K 线、公司详情） | 投资市场 › 行情 | 证券中心 › 行情与交易 |
| 交易 | 投资市场 › 交易（独立栏目） | 证券中心 › 行情与交易 → K 线下方的交易区（买/卖切换） |
| 公开企业资料（股份供给） | 投资市场 › 公司详情 | 证券中心 › 公司详情 |
| 上市 / 外部融资 / 接受或拒绝报价 / 股份回购 / 资本宣传 | 企业经营 › 股权与治理 | 证券中心 › 公司与资本 |
| 董事会提案、CEO 任免（自有公司） | 企业经营 › 股权与治理 | 个人 › 我的公司 › 公司治理（**保留**，原权限与确认不变；**只绑定当前管理公司**，见第 12 节） |
| 其它持股公司的股东权利 | 同上（同一页公司选择器） | 证券中心 › 公司与资本（公司选择器只在证券中心出现） |
| 持仓明细 | 投资市场 › 持仓 | 个人 › 股票持仓（只读：持股/成本/市值/盈亏；无 K 线、无买卖） |
| 存取款与个人贷款 | 个人生活 › 个人财务（银行现场追加） | 银行 › 银行业务 |
| 出资 / 分红 / 暂停 / 恢复 / 清算 / 推进到下一事件 | 企业财务页底部 | 个人 › 我的公司 › 日常经营（企业财务页保留一行指引） |
| 系统菜单 | Tab → 系统菜单 | Esc / HUD 菜单 |

交易区细节（合并后仍只有一处买卖入口）：

- 顺序固定：选股与行情摘要 → K 线 → 同一标的的交易区 → 持仓资料与全部标的表。
- 买/卖是**同一块表单**的两种模式，切换状态只存在内存；提交仍是原来的 `buy` / `sell` 命令各一次。
- 保留原有：数量输入、10/50/100 与「最多 N 股」「填入全部持仓」、可买/可卖数量、成交预览、
  价格影响、错误提示、原确认流程（卖出仍有确认框，价格或数量变化即重新确认）。
- 切换标的会清空买卖输入框与预览价格，不复用上一只股票的数量或成交价；共用 `selectedSecurityId`。

## 5. 房地产：明细与现场入口的保留

- 现场页（晴川公寓）**完整保留**：住所信息、休息/睡觉、住宅买入、挂牌/改价/撤销、储备土地受让、
  土地报价接受/拒绝、成交记录。仍复用 `renderEstate` 与 `EstateCommands`，未复制交易逻辑。
- 个人财务新增「房地产持有明细」：数据来自 `buildEstateView(state, false)` 的 `holdings`，
  逐项显示名称、类别（住宅/储备土地）、户型或面积、持有状态、取得成本、参考估值、未实现价差，
  以及「机构报价」提示（份数与最高报价，只读，不可在此接受或拒绝）；
  不含挂牌输入、买入/受让按钮与报价按钮，也不渲染在售房源目录与储备土地目录。
- 永久居住权仍不计入持有列表与净资产；净资产口径仍只走 `state` 里既有的 `netWorth`。
- 价格与挂牌版本确认、保护期、月度撮合、资金预留全部未改动；`EstateCommands`、`features/real-estate`、
  存档结构均无 diff。

## 6. 入口权限失效点（内存态，不写存档）

| 失效时机 | 机制 |
| --- | --- |
| 切换面板 / 关闭窗口 | `PanelManager.open()` 以新入口重算栏目；`close()` 清空 `entry` |
| 读档 | `applySnapshot` 关闭管理窗口（含入口上下文），由玩家重新走到设施前打开 |
| 新游戏 | `startNewGame` 已关闭窗口并清空会话 |
| 便利店购买 | 仍由 `activeShopId` 第二道校验（原有） |

`app/game.ts` 在玩家操作回调处按 `entry-policy` 拦截：银行类（存取款/贷款）、就业（入职/上班）、
证券买卖、资本业务（上市/融资/报价/回购/宣传）、治理（表决/任免）、房地产（买入/受让/挂牌/撤销/报价）、
竞选赞助。被拦时给出去哪里办理的提示，不静默失败；需要确认框的操作在**确认后提交前**再检查一次。
底层命令、AI 决策、定时模拟与月结完全不经过这层检查。

治理类回调额外核对**目标公司**：人物界面只接受当前管理公司（`buildBusinessView` 的 `canManage` + `id`），
证券中心沿用原业务权限（见第 12 节）。这项检查只决定调用能否到达命令，不改变 `capital.ts` 内部的
提案/任免判断，也不改股权计算与存档。

## 9. 已知限制

1. 证券中心没有独立的「持仓」栏目：必要持仓在行情页的持仓资料与「全部标的」表里；Tab 有只读持仓页。
2. Tab 的持仓详情浮窗不含 K 线（K 线只在证券中心）；卡片仍显示现价与涨跌幅，用于对照市值与盈亏。
3. 「市场与竞品」页沿用基线行为（AI 竞品公开概览），本轮未改其数据与文案，只把标签从
   「销售与营销」改为更准确的「市场与竞品」（定价/营销仍在「产品与研发」）。
4. 读档现在会关闭管理窗口（清理现场上下文），需要重新按 F 进入设施；这是本轮为满足
   「读档不得继承办理权限」而改变的唯一交互点。
5. 页面级栏目表（`ui/panels`）与命令级能力表（`app/entry-policy`）是两份表：前者决定「哪些页能看」，
   后者决定「哪些操作能提交」。两者概念相同但职责不同，若将来新增入口需要同时更新，已在报告中标注。
6. `src/app/personal-view.ts` 的「待发布产品」待办文案仍写「研发与产品」，而实际栏目名为
   「产品与研发」。这属于 `app` 层视图文案，超出本轮可改文件范围，**未修改**，建议由架构负责人一并调整。
7. `styles.css` 中原本给持仓卡片/浮窗画布用的 `.stock-card-chart` / `.stock-window-chart` / `.candle-canvas`
   已随手删除（K 线只在证券中心绘制）；未改动证券中心 K 线的样式。
8. 未做真机/浏览器验证（见第 10 节），移动视口下的具体折行留给用户验收。
9. **首轮结论的更正**：第一轮报告把「TAB 只显示自有公司治理」写成了已完成，但当时 TAB 治理页仍会沿用
   证券中心选过的公司（`query.capitalCompanyId` 未受约束），也没有按 `companyId` 做目标检查。
   该结论**不成立**，已在第 12 节按实际实现重写；当前实现以「当前管理公司」为唯一治理目标。

- 房地产：`EstateCommands`、`executePurchase`、挂牌版本与报价预留无 diff；现场按钮仅在晴川公寓渲染。

- 入口检查：确认框（卖出、回购、买住宅、受让土地、接受报价）在弹框后、提交前各检查一次；

  交易侧核对 `previewTrade` 的买入预算只取 `finance.accounts.savings`，因此「现金 > 0、存款 = 0」
  时界面显示的买入资金为 0、最大可买也为 0，不会误报购买力。

**已通过的类型检查与构建**

## 11. 拟追加的架构 / 契约条目（交由架构负责人统一更新）

**`docs/architecture.md` §1（ui 目录说明）**

- `ui/panels.ts`：由「五类入口 + 锁定」改为「按打开入口筛选栏目」；`ENTRY_SECTIONS` 是唯一可见性来源。
- 新增 `ui/stock-portfolio.ts` 仅渲染只读持仓（无图表）；`ui/estate-panel.ts` 增加只读持有明细区块。
- `app/entry-policy.ts`：玩家界面入口能力表（无经济副作用，不读不写状态）。

**`docs/contracts.md` 新增「界面入口与现场权限」小节（建议编号二十六）**

1. 一级栏目按打开入口筛选，未列入的栏目不得出现在导航里，也不得通过分类/待办/快捷入口进入；
   不允许「只隐藏顶层按钮、子页仍可点」。
2. 现场权限只存在会话内存（`PanelManager.entry`、`Game.activeShopId`），不进 `GameState`、不进存档；
   关闭窗口、读档、新游戏必须清空。
3. 玩家操作提交前经过 `app/entry-policy` 的入口检查；需要确认框的操作在提交前复检一次。
   该检查只拦界面入口，不替代也不放松业务校验。
4. 行情与交易同页，只有一个买卖入口；买/卖切换是内存 UI 状态，切换标的重置数量草稿与预览价格。
5. 资本业务（上市/融资/报价/回购/宣传）属证券中心；自有公司治理与任免保留在人物界面，
   **且只绑定当前管理公司（CEO）**：其它持股公司的股东权利在证券中心按公司办理，
   人物界面不得沿用证券中心的浏览选择。
6. 治理类玩家命令在提交流程中核对目标 `companyId`：入口为人物界面时只接受当前管理公司，
   入口为证券中心时沿用原业务权限；该检查不替代 `capital` 内部的提案/任免判断。
7. 人物界面只展示只读持仓与房地产明细（复用 `buildEstateView(state, false)` 的 `holdings`），
   不展示 K 线、整页交易/土地目录或远程可点的交易按钮。
8. 政治人口环形图只使用 12 个互斥群体的比例，禁止与 3 收入/4 利益边际混合成 7 扇区，
   禁止从显示文本反算比例或为凑 100% 改人口数据。
9. 玩家界面不再展示可模拟企业样本、群体画像、逻辑城区与本月结算明细；底层数据、统计与月结接口保留。

**`docs/decisions.md` 建议记录**

- 为什么把资本业务整体迁到证券中心、而把自有公司治理留在人物界面（权限与「现场」语义的一致性）。
- 为什么 Tab 不显示 K 线（避免持仓页变成第二处远程行情入口）。
- 为什么读档要关闭管理窗口（清理现场上下文，避免继承办理权限）。
- 为什么删除四类内部统计展示（玩家界面只呈现可解释的公开信息）。

## 12. 第二轮（首轮验收退回）修正

本轮只修两处差异，未重做 UI，未改业务命令、股权计算与存档。

### 12.1 根因

**治理目标串台**

1. `PersonalPanel` 只有一个会话级内存 query，证券中心的公司选择写进 `query.capitalCompanyId` 并一直保留；
   切回 TAB 治理时 `setScope` 只改 `capitalMode`，查询目标没变。
2. `buildCapitalView(state, companyId)` 优先返回 `companyId` 指向的公司，于是 TAB 治理直接渲染了 B。
3. 只把 query 置空也不够：`buildCapitalView` 在「没有管理公司」时会回退到玩家持股的第一家公司，
   没有管理公司时仍会把 B 的治理带进人物界面。
4. `app/entry-policy` 只判入口（personal/securities），不核对治理目标 `companyId`，命令层也没有目标检查。

**交易区资金口径**

`renderHoldingSide` 复用了 `money.availableText`（现金 + 银行存款），而 `previewTrade` 的买入预算只取
`state.finance.accounts.savings`，因此界面上显示的「可用于买入」大于真实购买力。

### 12.2 最小修复

| 位置 | 修复 |

| 同上 | `managedCompanyId()` 读上一份视图的 `company.canManage/id`，复用 CEO 语义，**不以是否持股替代管理身份** |

未改：`capital*.ts`、`equity`、存档、只读视图公共签名、`entry-policy` 的能力表结构（只复用）。

### 12.3 三个最小复验场景（静态走查）

1. **管理 A + 持股 B，证券中心选 B，再回 TAB 治理**：`bound` 取到 A，`buildCapitalView(A)` 返回 A，
   与 `company.id` 一致；治理页渲染 A，且不渲染公司选择器。B 的治理仍在证券中心可用（入口 `securities` 放行）。
2. **无管理公司但持有 B**：`canManage` 为 false，治理分支直接给指引，不渲染 B 的股权表；
   即使 `buildCapitalView` 回退到 B，界面也不会显示它。
3. **拒绝路径**：若 TAB 仍存在指向 B 的调用（旧按钮/旧事件），`guardGovernance` 在到达命令前拒绝并提示；
   证券中心同一次调用仍按原权限执行，未新增或收紧业务规则。

- `npm run typecheck`：通过。
