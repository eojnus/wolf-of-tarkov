## 3. 最小兼容架构（本轮执行基准）

### 3.1 入口与权限

原住宅 F 菜单增加「进入个人住宅」，UI 只渲染应用层提供的可进入状态与说明，回调交给 app。进入动作不产生房地产交易、扣费、房租结算或资产登记。

应用层在点击时校验：当前处于室外且没有切换请求；原菜单现场为 home；当前附近建筑 id 对应实际永久住所的 buildingId；当前 `freeResidenceOf` 仍返回该住所。首次仅接入 `home-001`，其他产权住宅不自动开放室内。不得使用 `owner.kind === 'player'`、净资产或房价判断居住权。

加载完成、真正提交切换前，再检查请求代次、游戏会话以及最新居住权与建筑对应关系。UI 隐藏/禁用按钮不是权限校验。不得把「室内退出门」伪造成可办理房地产的城市 home 现场；室内不允许通过旧菜单残留远程办理业务。

### 3.2 同一游戏与同一角色

保留唯一 Game、GameStore、RAF、renderer、camera、Player 与角色动画资源。进入只将同一个 `player.group` 从城市场景移到室内 scene，并改 pose、活动碰撞与相机参数；退出移回。不得重新 boot、new Game、createInitialState、store.replace 或重新加载角色来实现切换。

室内使用自己的 `THREE.Scene`，不塞进城市场景或城市楼体工厂。建议新增 `src/world/interiors/qingchuan.ts`（布局与场景）、`assets.ts`（确有需要时才分离加载与资源释放）；不要为了单套住宅建立通用住宅引擎、注册中心或家具管理系统。

World 维护仅内存的活动地点/切换状态，例如 outdoor → loading → indoor → outdoor，保存 residenceId、室外回归 pose 与相机、请求代次。可在 app 增加一个小型住宅进入协调文件，也可保持在 game 的私有方法，取修改最少且清楚者。world 不读取 GameState/房产/财务。

建议最小表现层接口形状（名称可调整，不是要求预建接口）：异步进入指定室内；退出/取消；查询是否在室内、是否切换中与门口可退出状态。仅实现本次真实调用的方法。避免修改现有业务公共接口。

### 3.3 按需加载、失败与资源释放

只有点击进入后才 `import()` 室内实现并读取家具 GLB/贴图。配置中的资源标识、URL 可预先存在；启动/靠近建筑/打开菜单不得 preload 模型。退出销毁室内 scene 的独有 geometry/material/texture、灯光和引用；浏览器 HTTP 缓存及已下载 JS 模块可保留，不长期保留家具 GPU 资源。

加载阶段仍显示室外，清空输入并锁人物移动/重复进入，不额外暂停经济模拟。所需房间和四类家具全部可用后才原子切入；任一必需模型失败则释放半成品，保持室外和可重试状态，明确提示，不能用方块静默顶替交付。

取消/读档/新游戏/dispose 都递增会话或请求代次。迟到成功结果立即 dispose；迟到失败与 finally 不得覆盖新会话状态。支持加载失败后再次尝试，失败 Promise 不永久缓存。取消可先做逻辑失效，不强求对共享 HTTP 请求进行物理中止。

室内独享资源按清晰所有权释放；同一个材质/贴图被多个家具使用时只释放一次。禁止通用遍历释放 Player、城市 BuildingVisualFactory 或全局 renderer 的共享资源。World.dispose 先失效室内请求、清理室内，再按现有城市销毁顺序处理其他资源。

室内活动时只渲染室内，不渲染室外；室外驻留原城市场景资源以便快速回归，无须重建整城。`pushEnvironment` 仍接收权威天气时间，但室内不更新室外雨幕、不执行室外 followCamera、不让室内 pose 驱动室外太阳位置；退出首帧按最新状态重新采样。保留当前环境契约，不新增天气/昼夜玩法。

### 3.4 碰撞、镜头与城市异步任务隔离

室内有独立运动碰撞、镜头遮挡碰撞、可走边界、入户落点及出口触发范围；切换时不要覆盖城市 handles/colliders 的权威引用。`syncLayout`、楼体异步回调、collisionReady、pendingRestorePose 与城市摄像机定位逻辑在室内不得把玩家推出房间、重设室内相机或恢复城市交互。

活动场景就绪状态与城市楼体加载就绪要分清：城市回调不能解锁未完成的室内加载，也不能在房间已就绪时阻止室内移动。城市经济触发的布局更新仍按原规则落地，不靠暂停全局模拟规避。

人物只用 X/Z 移动，不开发楼梯/跳跃/物理引擎。玄关用材质变化表现落尘区，地面保持可通行同高；隔断门和卫浴门可固定为打开/推拉收起状态，不新增门动画系统。

现有 1.5 米边界余量不能直接应用于小房间。优先在表现层为 `Player.update` 增加可选的边界余量参数或等价最小配置，默认保持室外 1.5 米，室内按角色半径与墙体几何计算。所有调用同步检查；不要假造扩大后的房间尺寸掩盖边界问题。movement 与 camera collider 分开，避免地板/天花板因二维 AABB 阻挡整间房；保留子步防穿透。

采用室内近距第三人称，不新增第一人称模式。室内相机距离、俯仰、近裁面等参数放配置；遮挡收缩优先，不得用舒适距离把相机推穿墙。必要时仅局部淡化遮挡玩家的自身网格并在退出恢复，避免永久改共享材质；不引入复杂后期。保存、退出与取消时还原原室外相机。

### 3.5 返回位置与存档

进入前记录室外完整 `WorldSaveData`，用当前城市布局、最终碰撞与 radius 验证回归点在 home 附近且安全。通常可保留当前合法交互位置；若需重新选择，依据当前建筑 entrance 与边界计算，不能写死 (-15.2,-19)。退出前再次核对现有建筑碰撞；有界候选搜索失败应明确处理，不无限循环，不把玩家传到楼内。

**本轮不持久化室内地点。** 加载中/室内时 `getSaveData()` 返回室外回归快照（含室外相机），经济、物品栏与其他 GameState 仍是保存瞬间的最新值。用户手动保存、自动保存和导出均沿用同一路径；不得为了保存临时传送人物。

因此从室内保存后重新读档，回到楼外安全位置；再次进入时固定家具布局保持。这是首轮明确的体验取舍，交付报告必须说明。不增加 world.location/residenceId 存档字段，不改 `SAVE.formatVersion = 19`、WorldSaveData 结构或迁移链。

读档/新游戏必须在 store.replace 引起订阅与布局同步之前失效并清理室内会话，再走原有 restore/reset。加载中的旧回调不得把新游戏或另一份存档拉回房间。普通进出不清空 simAccumulator/lastFrameMs、不调用 advanceGameTime、不触发 sleep/rest/monthly，不复制状态、背包或财务；模拟继续走原 tick。页面隐藏与暂停菜单仍按原有规则暂停。

## 4. 布局与家具执行标准

以用户策划 §2 为基准：约 3.3m × 6.2m、约 20.5㎡、净高约 2.55m；北入口，功能带深约 2.4m，西侧独立整体卫浴、东侧单排厨房，明确的服务区/起居室隔断；南端窗，浅木地面与暖白墙。

必须包含玄关与鞋柜、厨房（水槽/灶/柜/冰箱位）、卫浴（洗手台/马桶/淋浴或浴缸）、隔断门、卧室兼起居室、南窗及基础室内灯光。窗外用低成本简化都市背景，不二次渲染城市。窗向是室内局部布局决定，不要求物理嵌入室外楼体；室外 home 入口朝向与室内北入户不必硬性重排楼体。

单人床约 1×2m，桌约 1×0.55m，紧凑沙发约宽 1.2m，椅子合理贴桌且不堵出口。当前角色直径 0.84m，关键门口/过道净宽目标至少约 0.95m，需留少量容差；策划 0.75m 下限不能直接采用。允许在约 20㎡目标内调整服务区与摆位，不任意放大成人工豪宅，也不全局缩小人物。若确实无法兼容，报告具体尺寸问题再协调。

**以此次正式任务为准，床、沙发、桌、椅四类均须实际引入并摆放。** 策划想法库中的“空间不足可不摆沙发”不免除此项交付；优先换紧凑模型或调整位置。茶几、装饰、阳台可省略。建筑壳体、柜体和简单固定设施允许程序化制作，但不能把自制基本几何冒充四类外部模型。

每个固定家具保留稳定 assetId、实例 id、独立 Object3D、尺寸/变换和碰撞配置，关联本次 residenceId；不建立家具库存、购买记录、布局存档、编辑工具或未来接口空壳。尺寸、入口、镜头、加载参数集中 `src/content/config.ts`；如资产清单较长可放独立 content 文件并由配置引用，遵守现有约定。

## 8. 必要验收与交付

本次准备仅运行了一次基线 `npm run build`（内含 `tsc --noEmit`）：通过；Vite 报既有大包提示。没有运行游戏，也没有验证尚未实现的住宅功能。

实现交付前只做一次类型检查与生产构建；`npm run build` 已含类型检查，报告该事实即可，不必重复执行同一 tsc。失败修复后只重跑相关项。不要扩建 smoke、做全流程回归、长时模拟/压力或多浏览器矩阵。

以静态审查验证：进出不重置状态、不额外推进时间/月结、不改变产权；读档/新游戏失效顺序；室内存档返回室外；资源所有权与异步过期处理。仅有具体疑点时补一次性局部验证。

少量人工/局部运行检查（有工具可做一次紧凑巡检；未做的明确交用户）：

1. 原 F 住宅菜单、休息与房地产入口保留；进入按钮只在合法现场生效。
2. 进入、门口 F 离开、再次进入；出生点/回归点安全，输入与鼠标锁定无残留。
3. 一次巡走玄关→厨房过道→起居室→门口，检查隔断、卫浴与床/沙发/桌椅、窗和灯；确认净宽和镜头。
4. 初次进入前不请求家具，进入后有真实 GLB；离开不渲染/持有室内 GPU 资源。以代码及少量网络/资源观察为证，不做压力测试。
5. 室内保存并读档回楼外，最新余额/物品栏/住宅权利保留；经济随自然时间正常变化，不能要求进出前后金额绝对不变。
6. 加载失败或加载中读档/新游戏不会被迟到回调传回旧房间；优先静态审查，必要时仅局部复现。
