# 场景比例核对（scene-scale）

本文记录既有建筑与人物模型在《塔科夫之狼》世界里的真实比例核对结果，以及旧档碰撞安全的
最小处理。**本文的比例结论来自 GLB 包围盒实测数据 + `src/content/config.ts` 与
`src/world/scene.ts` 的几何核对，未实际打开浏览器做视觉验收**（详见文末“未验证项”）。

## 0. 现行口径：旧整栋 GLB 参照 ≠ 当前模块化路径（2026-10-27 接入后）

| 项目 | 旧整栋 GLB 时代（本文第 1–4 节记录的测量与结论） | 当前正式路径 |
| --- | --- | --- |
| 外观来源 | `applyBuildingModel` 加载 `assets/models/*.glb`，按实测参照等比缩放 | 模块化工厂按只读规划尺寸生成楼体 |
| 碰撞体 | 缩放后模型的世界包围盒，写回 `handle.collider` | 只读规划尺寸 + 朝向得到的声明包络，原地写同一对象 |
| 比例参照 | `content/scene-scale.ts` 的 `MODEL_SCALE_REFERENCES` | 不再参与运行时；尺寸精度由规划尺寸与 `plan.ts` 保证 |
| 加载失败表现 | 保留灰盒与配置 AABB | 保留占位外观并记录诊断（正常成功路径不回落） |

结论：**第 1–4 节是历史测量记录，仍然真实，但不再描述当前渲染与碰撞行为**；
`content/scene-scale.ts` 保留为只读参照数据，正式场景不再引用它。
人物 1.78 米的身高约定与“建筑以米制真实尺寸建模”这一条仍然有效。
当前模块化的尺寸/包络口径见 `docs/architecture.md` 第 16 节；历史报告可从 Git 查看，见 `docs/history.md`。

## 1. 测量口径与换算规则

- 下文“原始尺寸”是对 GLB 文件实际包围盒的测量值：**GLB 自身节点变换已生效、
  尚未乘游戏缩放、`minY = 0`**，单位与游戏世界一致（米）。
- **诚实说明**：既有五栋建筑的 GLB 都是**单 mesh**，没有门洞节点、也没有楼层层级；
  因此只能以“整栋包围盒高度”作为比例参照，**不能声称测量过门洞高度**。
  门洞、楼层宽度等没有可靠的模型内参照，本文不做任何门洞测量。
- 换算规则（`src/world/scene.ts#applyBuildingModel`）：
  - 有实测参照（`src/content/scene-scale.ts`）时：`scale = targetReferenceHeightMeters / sourceReferenceHeight`，
    用 `model.scale.setScalar(scale)` **等比**缩放——不做非等比拉伸、不压缩；
  - 无参照的模型（未来新增）保留旧的“三边约束取最小比例”回退；
  - 缩放后底面贴地、水平居中，建筑中心仍对齐 `config.position`；
  - 碰撞体写回**原 `handle.collider` 对象**（不替换引用），标签改为 `worldBox.max.y + 2.4`。
- 目标高度取自 `config.size.height`（`scene-scale.ts` 通过 `findBuilding` 读取，
  不在参照表里重复写数字）。旧五栋统一使用 `total-height` 参照。

等比系数 = 目标高度 ÷ 原始参照高度。

## 4. 碰撞与可达性结论（历史：旧 GLB 路径）

> 本节数字属于旧整栋 GLB 路径。接入模块化楼体后，六栋基础建筑的碰撞体一律等于规划 AABB
> （即配置 `position ± size/2`），不再有“模型比规划更大/更小”的差异；下表仅作历史对照。

碰撞体数据来自 `applyBuildingModel` 的最终世界包围盒（程序化便利店为配置 AABB）。
下表为缩放后的建筑碰撞盒范围（世界坐标，米）：

| 建筑 | x 范围 | z 范围 |
| --- | --- | --- |
| home | -22.50 … -19.50 | -20.50 … -17.50 |
| bank | 18.27 … 23.73 | -21.91 … -16.09 |
| office | -24.78 … -17.22 | 17.22 … 24.78 |
| securities | 16.55 … 25.45 | 15.51 … 26.49 |
| government | -4.09 … 4.09 | -46.05 … -41.96 |
| convenience（配置 AABB） | -8.00 … 8.00 | 40.00 … 52.00 |

- **建筑中心未变**：缩放、贴地、居中都以 `config.position` 为基准，六栋建筑的世界中心不变。
- **道路未重叠**：横向主干道 z ∈ [-6, 6]，纵向主干道 x ∈ [-6, 6]（纵向路面北端止于 z = 40）。
  所有建筑碰撞盒到车道边缘的间距均 ≥ 约 10 m：securities 西边界 x = 16.55、office 东边界
  x = -17.22、home 北边界 z = -17.50、bank 北边界 z = -16.09；government 与道路也不重叠。
  securities 进深虽然从 10 m 扩到 10.99 m（z 15.51…26.49），但仍未与任何道路或其他建筑重叠。
- **便利店入口可达**：入口点 (0, 39.8) 位于便利店碰撞盒 z = 40 的外侧 0.2 m；纵向道路北端
  正好接到门前（z → 40），门前铺装/踏步在 z ≈ 35.9…40.1。人物半径 0.42 m，最近可站到
  z ≈ 39.58；`interactionDistance = 2.5`，从路面上即可进入交互范围，不需要进入建筑内部。
- **摄像机继续使用 collider**：`world.ts#placeCamera` 仍以 `handle.collider` 做射线-AABB 避障，
  建筑比例调整后自动跟随新的碰撞盒，没有第二套遮挡数据。
- **旧档碰撞安全（`world.ts#ensurePlayerNotInsideBuildings`）**：
  - 人物中心落入任一建筑碰撞盒**外扩 `PLAYER.radius`** 的 AABB 时，按东/西/南/北四方向的
    最小位移推到刚好在盒外；只改位置，**朝向沿用存档原值**；
  - 结果再夹到 `±(CITY.groundSize / 2 − 1.5)`，与人物移动的边界口径一致；
  - 只在 `loadBuildingModels()` 全部完成后调用一次、在 `restore()` 末尾调用一次，
    不进入渲染循环；正常位置不做任何位移；**不无条件传送回出生点、不改存档格式**。
  - 典型例子：旧档若贴着 securities 旧西面存档（z ≈ 16.0），新碰撞盒北扩约 0.49 m 后人物
    会落入外扩区，逻辑会把人向南推到 z ≈ 15.09（最小位移），而不是传送回出生点。

## 5. 未验证项

- **未实际打开浏览器做视觉验收**：比例结论来自 GLB/USDZ 包围盒实测数据加 `config.ts` / `scene.ts` 几何核对。
  2026-10-31 只在 Electron 生产构建中观察了 Alina 在道路上的整体比例，没有走近门洞、家具或室内做近距离穿模检查。
- 按任务要求，场景子任务本身未运行 `tsc --noEmit` / `vite build` / 测试脚本；主 agent 已在
  集成后统一执行类型检查与生产构建（结果见最终交付说明），本文比例结论不依赖构建结果。
- 人物没有垂直位移，门前 0.20 m 铺装 / 0.35 m 踏步在视觉上可能轻微遮挡脚部，未做运行验证。
- 五栋旧 GLB 为单 mesh、无门/楼层节点，因此门洞、楼层高度的“真实比例核对”无法进行，
  本文只能核对整栋高度；便利店门洞尺寸是程序化定义值，不是模型测量值。
- `home` 的原始模型非常细长（0.5×2.0×0.5），按配置目标高度 12 m 等比缩放后占地约
  3.0×3.0 m。该结果与旧实现相同，不是本轮新增的失真；本轮不替换资产、也不改配置高度，
  仅在此如实记录为已知表现限制。
